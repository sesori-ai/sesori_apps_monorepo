# Step 5 — Status semantics + dead control-protocol removal

Date: 2026-08-28.

## Delivered

- Changed `ControlStatusNotifier` to reduce the lifecycle service's already
  eligible plugin metadata: aggregate health is degraded iff any eligible
  plugin is degraded or failed, and healthy otherwise. Dormant/not-installed
  and zero-eligible snapshots are therefore healthy; eligibility remains owned
  by `PluginLifecycleService`, not the notifier.
- Removed the unpublished control-channel `token_update`, `restart`, and
  `provision_progress` variants from the shared sealed union and regenerated its
  Freezed/JSON outputs. Removed `ControlPluginHealthState.unavailable`; `unknown`
  remains the forward-compatible parse fallback.
- Removed the bridge provision notifier, runtime-progress wire mapper, generated
  progress DTO, tests, exports, composition, bridge/client dispatcher branches,
  and affected development-harness commands. Internal runtime provisioning and
  terminal rendering remain intact.
- Reduced supervised token authority to its declared pull-on-demand contract.
  `ControlChannelTokenService` still correlates requests, invalidates on null
  replies, and preserves newest-issued ordering across concurrent pulls; no
  unsolicited token write path remains.
- Updated both inbound dispatchers to exhaustively classify the smaller union
  while preserving their one-subscriber and direction-ownership boundaries.
- Added explicit verification that a supervised restart latches exit 86 before
  shutdown, the existing coordinator backstop runs emergency plugin disposal
  when teardown hangs, and forced exit preserves the latched sentinel. No
  second watchdog or lifecycle mechanism was added.
- Updated the development harness, regression contract, plan complexity, and
  stale token-push comments. No compatibility shim was retained because this
  local control wire has never shipped publicly and all consumers update here.

No rendered UI or database behavior changes. The internal supervised status
contract is now setup-aware, and the unpublished control wire is smaller.

## Architecture implementation review

Approved 2026-08-28 with B-Bridge, B-Shared, and B-Client applied and no
findings. The reviewer confirmed eligibility stays in the lifecycle service,
status only reduces lower-layer metadata, provisioning stays internal/terminal,
pull correlation stays in the token service, DTO removal updates every
producer/consumer in lockstep, dispatchers remain directional and exhaustive,
and restart verification reuses the existing coordinator/backstop owner.
