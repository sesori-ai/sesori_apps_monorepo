# Unsigned native desktop bundles

Use the repository-pinned Flutter/Dart SDK on the target OS/CPU. Resolve the client
workspace with `flutter pub get --enforce-lockfile`, and commit source changes before
building. From `client/desktop`:

```bash
dart run tool/stage_desktop_bundle.dart \
  --build-number 1 \
  --output ../../build/desktop-bundle-1
```

The output must not already exist. The producer builds the bridge and release GUI
from that checkout, enforces dependency locks, checks the helper's reported version,
and embeds one `DesktopBundleIdentity` in both the GUI and helper manifest.

- macOS payload: `<output>/Sesori.app`; complete helper at
  `Contents/Helpers/bridge/`.
- Windows/Linux payload: `<output>/bundle`; complete helper at `bridge/`.
- The helper keeps its generated `bin/` and `lib/` layout. Do not copy its executable
  alone or modify native-asset metadata.
- `dart-defines.env` is build metadata, not a credential file.
  `build-source-changes.patch` records native project changes generated by the build.
- macOS GUI/frameworks may remain universal; the complete package is architecture-
  specific because its helper is native to the build target. Wrong-host identity
  checks refuse mixed-architecture supervision; this is not a universal package.

These are **unsigned staging outputs**, not installers or signed release evidence.
Platform packaging must apply the required signing/notarization and actual artifact
install/upgrade gates before publication. Nothing here publishes releases, downloads
harnesses, or modifies the standalone CLI installation or application data.

Release builds require the matching staged helper and compiled identity. For local
repository helpers or `SESORI_DESKTOP_BRIDGE_PATH`, use debug/profile builds instead.
Product semantic-version bumps include desktop through `make bump-version`; desktop
build numbers and release channels remain independently owned.
