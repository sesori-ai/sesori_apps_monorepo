Instant new session — the eleven decisions

Your five answers reshaped the plan into eight steps, and they raised eleven smaller decisions along the way. Nine need you; two are recorded at the bottom with no real alternative. Each has a recommendation — including one where I recommend against what you suggested, because it loses data (D1).

Settled by your answers

  • The composer stays live; extra messages queue until the session exists.
  • A placeholder row appears in the session lists right away.
  • Two happy discoveries: follow-ups need no new queue (the existing one already accepts prompts for a session that is not loaded), and running rows already lead Today, so the placeholder and the real session occupy the same slot — the list does not move when they swap.

Decisions

D1Creation fails and you had already typed follow-upsPick one

Your first message goes back into the composer, as you asked. The open part is what happens to the extra messages queued behind it. Your suggestion was to append them into the same draft, separated by blank lines — I recommend against it, for a concrete reason: a follow-up can carry attachments, and text has nowhere to put them, so images would be silently dropped. It also merges turns you deliberately separated, and a queued slash command cannot be appended to a text draft at all.

D2What the launching row looks like in the listPick one

It has to be the same 70 px shape as a real row or the list jumps when the real session replaces it. That fixes most of it; the question is the title and the meta line.

D3What happens if you tap the launching rowPick one

There is no session to open yet. It could instead take you back to the screen where your message is already showing.

D4Do the filter chips count it, and does search match it?Pick one

The All/Running/Unread chips show exact counts of the loaded list, and the search field narrows loaded titles. The launching row is not a loaded session. (Separately and not in question: the list's empty state must treat it as content — a project's first session is the commonest path here, and "no sessions yet" above a launching row would be plainly wrong.)

D5Creation fails after you have left the screenPick one

Today a late failure is silent, because nothing had promised you anything. With the placeholder row, a session is now being visibly promised in every list.

D6Starting a second session while the first is still launchingPick one

On desktop this is easy to reach: the home composer and a project composer are separate surfaces.

D7Dictation stays alive during creationPick one

Today the composer is unmounted at Send, and that is what releases the phone's voice resources. Keeping it live (which is the point of your Q3 answer) keeps dictation alive for the few seconds creation takes.

D8On desktop the composer has to move at SendPick one

The idle new-session composer sits inline in a centred column; a session's composer is anchored to the bottom. Since it now stays mounted, it has to travel. The only question is whether you see it happen.

D9Can you still change harness, model or worktree while it creates?Pick one

Send commits those to a request already in flight, and the queued follow-ups inherit them.
