This does not remove the conversation

The reduction targets tool-state text. It does not strip ordinary assistant prose or reasoning text.

  • Tool identity and lifecycle status are retained.
  • Existing attachment delivery remains in place.
  • Subtask identity, description and child links remain.
  • This branch does not change the permission/question flow or file-change signals.

Shell visibility is not yet uniform

The bridge keeps shell results only when the owning adapter supplies explicit command evidence. A tool’s display title or generic “execute” kind is not enough.

Suggested decision before merge

Recommendation · not implemented

Reduce bulk, not the explanation.

Keep the lightweight-card direction, but retain enough context to tell what ran and why it failed. These are proposed follow-ups, not changes already included in the branch.

  1. Keep bounded failure explanations for non-shell tools, instead of dropping every error body.
  2. Keep a short operation/target summary where a backend supplies meaningful data. Avoid forwarding entire raw inputs or file contents.
  3. Complete and verify the missing shell mappings before treating command/result visibility as consistent across harnesses.

The missing text is removed at the common bridge projection, before live delivery and new chat-history capture. It is not simply collapsed in the UI. Existing already-stored rows are not migrated by this change.

Evidence & limits

A behavior review, not a release certification. The examples are designed to make an implementation policy visible to the team.

What was verified

  • 75 focused projection tests passed at branch source 09c63c858, after the latest main merge.
  • Backend-shaped OpenCode read success/failure and shell success were executed through the real plugin mapper and common bridge projection.
  • A generic ACP execute failure was executed through both live and replay. Both produced execute / Failed with no output/error text.
  • Widget source confirms how titles, commands, status, output and errors become visible cards.

Passing tests confirm the current retention policy. They do not prove that the removed information is unimportant.

What is not claimed

  • No new phone/desktop screenshot capture or end-to-end app run was performed for this report.
  • No real-harness session was run for each mapping gap. The ACP example is a representative protocol-shaped reproduction.
  • Illustrations approximate shared widget styling; typography, exact theme colors and device dimensions may differ.
  • No measured latency, bandwidth percentage or battery improvement is claimed.
  • Before/after refers to fixed Git revisions. Later branch changes may supersede this report.
